# 目录结构调整实施指南

## 一、关于 backend/ 目录的识别问题

### 问题说明
如果直接将后端模块移动到 `backend/` 目录，需要同步修改父 POM 的 `<modules>` 配置，否则 Maven 和 IDE 无法识别。

### ⚠️ 建议方案：**不急于调整目录结构**

考虑到目录结构调整的风险和工作量，建议采用以下策略：

---

## 二、推荐实施方案

### 方案 A：渐进式优化（推荐）⭐

**阶段 1：仅优化命名规范（风险最低）**

```
base_admin/                       # 保持当前结构
├── base-admin-common/            # 重命名：base_admin_common → base-admin-common
├── base-admin-framework/         # 重命名：base_admin_framework → base-admin-framework  
├── base-admin-system/            # 重命名：base_admin_system → base-admin-system
├── base-admin-web/               # 重命名：base_admin_web → base-admin-web
├── base-admin-quartz/            # 重命名：base_admin_quartz → base-admin-quartz
├── base-admin-sse/               # 重命名：base_admin_sse → base-admin-sse
├── base_admin/                   # 前端（保持不变）
├── todo-app/                     # Todo Web
├── todo-desktop/                 # Todo 桌面
├── docs/                         # 新增：文档目录
│   ├── design/
│   │   ├── workflow-engine.md
│   │   └── document-processing.md
│   └── ui-reference/
│       └── document-processing-ui.html
├── pom.xml
└── README.md
```

**操作步骤：**

1. **重命名模块目录**
```bash
# 在项目根目录执行
mv base_admin_common base-admin-common
mv base_admin_framework base-admin-framework
mv base_admin_system base-admin-system
mv base_admin_web base-admin-web
mv base_admin_quartz base-admin-quartz
mv base_admin_sse base-admin-sse
```

2. **修改父 pom.xml**
```xml
<modules>
    <module>base-admin-web</module>
    <module>base-admin-system</module>
    <module>base-admin-common</module>
    <module>base-admin-framework</module>
    <module>base-admin-sse</module>
    <module>base-admin-quartz</module>
</modules>
```

3. **修改各子模块 pom.xml 中的 artifactId**
```xml
<!-- base-admin-common/pom.xml -->
<artifactId>base-admin-common</artifactId>

<!-- base-admin-framework/pom.xml -->
<artifactId>base-admin-framework</artifactId>

<!-- 其他模块类似... -->
```

4. **刷新 IDE**
```bash
# IntelliJ IDEA
右键项目 → Maven → Reload Project

# 或使用命令行
mvn clean install
```

**优点：**
- ✅ 风险低，只是重命名
- ✅ 符合 Maven 命名规范
- ✅ IDE 和 Maven 可以自动识别
- ✅ 不影响现有功能

### 方案 B：完整目录分离（需要更多调整）

如果确实要实现 `backend/` 和 `frontend/` 的完整分离：

```
base_admin/
├── backend/                      # 后端根目录（新增一层）
│   ├── base-admin-common/
│   ├── base-admin-framework/
│   ├── base-admin-system/
│   ├── base-admin-web/
│   ├── base-admin-quartz/
│   ├── base-admin-sse/
│   └── pom.xml                   # 后端父 POM
├── frontend/                     # 前端根目录
│   ├── admin/                    # 主后台（重命名 base_admin）
│   ├── todo-app/
│   └── todo-desktop/
├── docs/                         # 文档
├── scripts/                      # 脚本
└── README.md
```

**需要的调整：**

1. **移动文件并创建新的父 POM**

```bash
# 创建 backend 目录
mkdir backend

# 移动所有后端模块
mv base-admin-* backend/
mv pom.xml backend/pom.xml

# 创建根目录的聚合 POM
```

2. **创建新的根 pom.xml**（聚合前后端）

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 
         http://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <groupId>com.clm</groupId>
    <artifactId>base-admin-parent</artifactId>
    <version>1.0-SNAPSHOT</version>
    <packaging>pom</packaging>

    <name>Base Admin Parent</name>

    <modules>
        <module>backend</module>
    </modules>

    <build>
        <plugins>
            <!-- 前端构建插件 -->
            <plugin>
                <groupId>com.github.eirslett</groupId>
                <artifactId>frontend-maven-plugin</artifactId>
                <version>1.15.0</version>
                <configuration>
                    <workingDirectory>frontend/admin</workingDirectory>
                </configuration>
                <executions>
                    <execution>
                        <id>install node and npm</id>
                        <goals>
                            <goal>install-node-and-npm</goal>
                        </goals>
                        <configuration>
                            <nodeVersion>v18.18.0</nodeVersion>
                        </configuration>
                    </execution>
                    <execution>
                        <id>npm install</id>
                        <goals>
                            <goal>npm</goal>
                        </goals>
                        <configuration>
                            <arguments>install</arguments>
                        </configuration>
                    </execution>
                    <execution>
                        <id>npm run build</id>
                        <goals>
                            <goal>npm</goal>
                        </goals>
                        <configuration>
                            <arguments>run build</arguments>
                        </configuration>
                    </execution>
                </executions>
            </plugin>
        </plugins>
    </build>
</project>
```

3. **修改 backend/pom.xml**

```xml
<project>
    <modelVersion>4.0.0</modelVersion>

    <!-- 移除 parent，因为它本身就是父模块 -->
    <parent>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-parent</artifactId>
        <version>3.2.0</version>
    </parent>

    <groupId>com.clm</groupId>
    <artifactId>base-admin-backend</artifactId>
    <version>1.0-SNAPSHOT</version>
    <packaging>pom</packaging>

    <modules>
        <module>base-admin-common</module>
        <module>base-admin-framework</module>
        <module>base-admin-system</module>
        <module>base-admin-web</module>
        <module>base-admin-quartz</module>
        <module>base-admin-sse</module>
    </modules>

    <!-- 其他配置保持不变 -->
</project>
```

4. **刷新 IDE 项目**

在 IntelliJ IDEA 中：
- 关闭项目
- 删除 `.idea` 目录
- 重新打开项目，选择 **根目录的 pom.xml** 作为 Maven 项目

**缺点：**
- ⚠️ 修改较大，需要仔细测试
- ⚠️ CI/CD 脚本需要同步修改
- ⚠️ 开发环境配置需要更新

## 三、IDE 识别问题解决方案

### IntelliJ IDEA

**问题：**移动后 IDE 无法识别 Maven 模块

**解决方法：**

1. **方法 1：重新导入**
```
File → Close Project
删除项目根目录的 .idea 文件夹
File → Open → 选择根 pom.xml
```

2. **方法 2：刷新 Maven**
```
右键根 pom.xml → Maven → Reload Project
或点击右侧 Maven 工具栏的刷新按钮
```

3. **方法 3：标记目录**
```
如果某些模块未识别：
右键模块目录 → Mark Directory as → Sources Root
```

### Eclipse

```
右键项目 → Maven → Update Project
勾选 Force Update of Snapshots/Releases
```

### VS Code

```
重新加载窗口：
Ctrl+Shift+P → Reload Window
```


**IntelliJ IDEA:**
- 打开右侧 Maven 工具窗口

**检查点：**
- ✅ 所有模块都在 Maven 窗口中显示

## 五、最终建议

### 对于您的项目，我建议：

#### 🎯 **立即执行（方案 A - 模块重命名）**

1. ✅ 重命名模块：`base_admin_xxx` → `base-admin-xxx`
2. ✅ 整理文档：移动 MD 和 HTML 到 `docs/` 目录
3. ✅ 更新父 pom.xml 的 modules 配置

**原因：**
- 风险低，改动小
- 符合 Maven 规范
- IDE 和工具链完全兼容
- 不影响开发和部署流程

#### ⏳ **延迟执行（方案 B - 完整分离）**

如果未来需要：
- 前后端完全独立部署
- 不同团队维护前后端
- 需要独立的 CI/CD 流程

那时再考虑完整的 `backend/` 和 `frontend/` 分离。

## 六、快速操作脚本

### Windows PowerShell 脚本（推荐用于方案 A）

```powershell
# rename-modules.ps1

Write-Host "开始重命名 Maven 模块..." -ForegroundColor Green

# 重命名目录
Rename-Item -Path "base_admin_common" -NewName "base-admin-common"
Rename-Item -Path "base_admin_framework" -NewName "base-admin-framework"
Rename-Item -Path "base_admin_system" -NewName "base-admin-system"
Rename-Item -Path "base_admin_web" -NewName "base-admin-web"
Rename-Item -Path "base_admin_quartz" -NewName "base-admin-quartz"
Rename-Item -Path "base_admin_sse" -NewName "base-admin-sse"

# 创建 docs 目录
New-Item -ItemType Directory -Path "docs\design" -Force
New-Item -ItemType Directory -Path "docs\ui-reference" -Force

# 移动文档
Move-Item -Path "工作流引擎实现方案.md" -Destination "docs\design\workflow-engine.md"
Move-Item -Path "智能文档处理实现方案.md" -Destination "docs\design\document-processing.md"
Move-Item -Path "智能文档处理UI参考.html" -Destination "docs\ui-reference\document-processing-ui.html"

Write-Host "重命名完成！" -ForegroundColor Green
Write-Host "请手动执行以下操作：" -ForegroundColor Yellow
Write-Host "1. 修改父 pom.xml 中的 <modules> 配置" -ForegroundColor Yellow
Write-Host "2. 修改各子模块 pom.xml 中的 <artifactId>" -ForegroundColor Yellow
Write-Host "3. 在 IDE 中 Reload Maven Project" -ForegroundColor Yellow
```

**执行：**
```powershell
# 在项目根目录执行
.\rename-modules.ps1
```

## 七、常见问题

### Q1: 重命名后编译报错？
**A:** 检查是否修改了所有 pom.xml 中的模块名称，特别是依赖引用部分。

### Q2: IDE 无法识别模块？
**A:** 尝试删除 `.idea` 目录，重新导入项目。

### Q3: 依赖无法解析？
**A:** 执行 `mvn clean install` 确保所有模块都安装到本地仓库。

### Q4: 是否需要修改 Java 代码中的 package？
**A:** 不需要！只是修改模块名称，package 路径保持 `com.clm.*` 不变。

## 总结

**对于您的问题 "放 backend/ 会识别到吗"：**

- ❌ 直接移动到 `backend/` **不会自动识别**
- ✅ 需要同步修改父 POM 的 `<module>backend/xxx</module>`
- ✅ 或者使用我推荐的**渐进式优化方案 A**（只重命名，不改变层级）

**建议先采用方案 A**，等项目稳定后，如果确实需要完整分离，再考虑方案 B。
